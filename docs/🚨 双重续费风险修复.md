## ⚠️ 严重问题发现

**发现时间**：2025-11-10  
**严重等级**：🔴 **极高**（可能导致用户被双重扣款）  
**影响范围**：所有升级/降级/换周期的用户  
**状态**：✅ 已修复

---

## 🔍 问题分析

### 问题场景

#### 场景：用户从 Basic Monthly 升级到 Pro Monthly

**时间线**：

```
Day 1 (2025-11-01):
用户购买 Basic Monthly
└─ Creem 订阅 A: sub_basic_123
   ├─ product: Basic Monthly
   ├─ status: active
   └─ auto_renew: ✅ 开启

Day 15 (2025-11-15):
用户升级到 Pro Monthly
└─ Creem 订阅 B: sub_pro_456
   ├─ product: Pro Monthly
   ├─ status: active
   └─ auto_renew: ✅ 开启

⚠️ 订阅 A 仍然存在，未被取消！

Day 30 (2025-12-01):
订阅 A 到期 → 自动续费
├─ Creem 扣款：$4.99  ❌ 不应该扣
└─ 发送 subscription.paid (sub_basic_123)

Day 30 (2025-12-15):
订阅 B 到期 → 自动续费
├─ Creem 扣款：$9.99  ✅ 应该扣
└─ 发送 subscription.paid (sub_pro_456)

结果：用户被双重扣款 $4.99 + $9.99 = $14.98 ❌
```

---

### 为什么会发生？

#### 我们的系统（Supabase）

```typescript
// ✅ 使用 upsert，基于 user_id
await supabase
  .from("user_subscriptions")
  .upsert({
    user_id: userId,
    tier: "pro",  // 新套餐
    creem_subscription_id: "sub_pro_456",  // 覆盖旧的
  }, {
    onConflict: "user_id"  // 一个用户只有一条记录
  })
```

**数据库中**：
```
Before: 
user_id: xxx, tier: basic, creem_subscription_id: sub_basic_123

After:
user_id: xxx, tier: pro, creem_subscription_id: sub_pro_456
      ↑ 覆盖了！旧的 sub_basic_123 丢失
```

---

#### Creem 那边

```
用户邮箱: user@example.com

订阅列表:
┌─ Subscription A ──────────────┐
│ ID: sub_basic_123             │
│ Product: Basic Monthly        │
│ Status: active  ← ⚠️ 仍活跃    │
│ Auto Renew: ✅                │
│ Next Bill: 2025-12-01         │
└───────────────────────────────┘

┌─ Subscription B ──────────────┐
│ ID: sub_pro_456               │
│ Product: Pro Monthly          │
│ Status: active                │
│ Auto Renew: ✅                │
│ Next Bill: 2025-12-15         │
└───────────────────────────────┘
```

**问题**：
- ❌ 两个订阅都是 `active`
- ❌ 两个都会自动续费
- ❌ 用户被双重扣款

## ✅ 解决方案

### 核心思路

**在激活新订阅时，自动取消旧订阅**

### 实施逻辑

```typescript
// 1️⃣ 查询现有订阅
const { data: existingSubscription } = await supabase
  .from("user_subscriptions")
  .select("*")
  .eq("user_id", userId)
  .single()

// 2️⃣ 判断是否为相同套餐
const isSamePlan = (
  existingSubscription.tier === newTier &&
  existingSubscription.billing_cycle === newCycle
)

// 3️⃣ 如果不是相同套餐，取消旧订阅
if (!isSamePlan && 
    existingSubscription.creem_subscription_id && 
    existingSubscription.creem_subscription_id !== subscription_id) {
  
  console.log("🔄 [Webhook] Canceling old subscription to prevent duplicate renewals")
  
  try {
    await creemClient.cancelSubscription(
      existingSubscription.creem_subscription_id
    )
    console.log("✅ [Webhook] Old subscription canceled")
  } catch (error) {
    console.error("⚠️ [Webhook] Failed to cancel old subscription:", error)
  }
}
```

async cancelSubscription(subscriptionId: string) {
  const response = await fetch(
    `${this.apiUrl}/v1/subscriptions/${subscriptionId}/cancel`,
    {
      method: "POST",
      headers: {
        "x-api-key": this.apiKey,
      },
    }
  )
  
  if (!response.ok) {
    throw new Error(`Creem API Error: ${await response.text()}`)
  }
  
  return response.json()
}

## 📝 代码实现细节

### 判断条件

```typescript
if (
  !isSamePlan &&  // ✅ 不是相同套餐
  existingSubscription.creem_subscription_id &&  // ✅ 有旧订阅 ID
  existingSubscription.creem_subscription_id !== subscription_id  // ✅ 旧订阅 ≠ 新订阅
) {
  // 取消旧订阅
}
```

**为什么要这三个条件？**

1. **`!isSamePlan`**：
   - 续费不需要取消（只是延长）
   - 升级/降级/换周期需要取消

2. **`existingSubscription.creem_subscription_id`**：
   - 确保有旧订阅 ID
   - 首次购买没有旧订阅

3. **`!== subscription_id`**：
   - 确保旧订阅 ≠ 新订阅
   - 防止取消自己（虽然不太可能）

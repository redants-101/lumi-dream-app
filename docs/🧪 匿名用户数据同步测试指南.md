# 🧪 匿名用户数据同步测试指南

## 📋 修复内容

### 问题描述
- **原问题**：登出后直接清空 localStorage 的使用数据，导致匿名用户的使用记录丢失
- **影响**：用户登出后可能"重新获得"已用完的次数，造成限制绕过漏洞

### 解决方案
1. ✅ 登出时先查询 `anonymous_usage` 表（基于 IP）
2. ✅ 如果有使用记录 → 同步到 `lumi_usage_data_v2` (localStorage)
3. ✅ 如果没有记录 → 初始化为空状态
4. ✅ 确保使用数据持续准确，无法通过登出绕过限制

## ✅ 测试步骤

### 测试 1：有使用记录的情况

**场景**：用户登录前作为匿名用户使用了 3 次，登录后再登出

#### 步骤：
1. **清除所有数据**（确保干净环境）
   ```javascript
   // 在 Console 中运行
   localStorage.clear()
   ```

2. **匿名状态使用 3 次**
   - 访问 `http://localhost:3000`（未登录）
   - 使用梦境解析功能 3 次
   - 查看 localStorage：`lumi_usage_data_v2` 显示 `dailyCount: 3, monthlyCount: 3`

3. **登录账号**
   - 点击 "Sign In" → 使用 Google/GitHub 登录

4. **使用 2 次**（已登录状态）
   - 使用梦境解析功能 2 次
   - 数据库 `usage_tracking` 表：`daily_count: 2, monthly_count: 2`

5. **登出**
   - 点击用户头像 → "Sign out"
   - 观察控制台日志

#### 预期结果：

**控制台日志**：
```
[Auth] 🚪 Starting sign out process...
[Auth] ✅ User data cleared (except usage data)
[Auth] 📊 Fetching anonymous usage from database...
[UsageService] 📊 Fetching anonymous usage for IP: xxx.xxx.xxx.xxx
[UsageService] ✅ Anonymous usage found: daily=3, monthly=3
[Auth] ✅ Anonymous usage synced to localStorage: {dailyCount: 3, monthlyCount: 3, ...}
[Auth] ✅ User signed out successfully
```

**localStorage 检查**：
```json
lumi_usage_data_v2: {
  "dailyCount": 3,
  "monthlyCount": 3,
  "lastUpdated": "2025-11-03T10:30:00.000Z",
  "day": "2025-11-03",
  "month": "2025-11"
}
```

**关键验证**：
- ✅ 使用数据**恢复为登录前的 3 次**（不是 0 次）
- ✅ 用户无法通过"登录-登出"绕过限制
- ✅ 数据来自数据库，不是前端伪造

## 🚨 潜在问题与解决

### 问题 1：IP 变化导致数据不一致

**场景**：用户登录前在 IP_A，登出后切换到 IP_B

**影响**：
- 登出时同步的是 IP_A 的数据
- 但实际使用的是 IP_B（不同的限制）

**解决方案**：
- ✅ 这是正确的行为（IP 级别限流设计）
- ✅ 用户切换 IP 后，应该有新的限制额度
- ✅ localStorage 只是缓存，真实验证在后端

---

### 问题 2：并发登出可能导致数据竞争

**场景**：用户在多个标签页同时登出

**影响**：
- 多次调用 `/api/anonymous-usage`
- localStorage 可能被覆盖多次

**解决方案**：
- ✅ 最后一次写入生效（幂等操作）
- ✅ 数据来源相同（同一 IP 的数据库记录）
- ✅ 无实质性影响

---

### 问题 3：数据库延迟导致旧数据

**场景**：用户刚使用完立即登出，数据库还未同步

**影响**：
- 登出时读取的是旧数据（少 1 次）
- 用户可能"多获得"1 次使用机会

**解决方案**：
- ⚠️ 可接受的延迟（1-2 秒内会同步）
- ✅ 后端验证是最终真相（前端只是缓存）
- ✅ 用户下次使用时会被后端限制

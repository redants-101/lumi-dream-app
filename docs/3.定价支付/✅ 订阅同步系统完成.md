## 🎯 功能概述

实现定期订阅同步功能，作为 Webhook 的备份机制，确保本地数据库与 Creem 平台的订阅状态始终保持一致。

### 为什么需要定期同步？

虽然我们已经有了 Webhook 来实时接收订阅变更，但是：

| 问题 | 说明 | 影响 |
|------|------|------|
| **Webhook 可能失败** | 网络问题、服务器故障 | 本地数据过时 |
| **Webhook 可能丢失** | Creem 发送失败 | 状态不一致 |
| **人为修改** | Creem 后台手动操作 | 无 Webhook 通知 |
| **时间漂移** | 周期时间可能不准确 | 续费日期错误 |

**定期同步** 可以作为安全网，确保即使 Webhook 失败，数据也能最终保持一致。

**功能**:

- ✅ 记录详细的同步日志
- ✅ 支持测试模式
- ✅ Cron Secret 验证

**同步逻辑**:
```typescript
// 判断是否需要更新
function shouldUpdateSubscription(local, creem) {
  // 1. 检查状态是否不一致
  if (local.status !== creem.status) return true
  
  // 2. 检查周期结束时间（允许 1 小时误差）
  const timeDiff = Math.abs(local.current_period_end - creem.current_period_end)
  if (timeDiff > 1 hour) return true
  
  return false
}
```

## 🔄 同步流程

### 完整同步流程

```
1. Cron Job 触发（每 6 小时）
    ↓
2. 查询本地所有活跃订阅
   SELECT * FROM user_subscriptions
   WHERE status IN ('active', 'canceled')
     AND creem_subscription_id IS NOT NULL
    ↓
3. 遍历每个订阅
    ↓
4. 调用 Creem API
   GET /v1/subscriptions/{subscription_id}
    ↓
5. 对比状态
   - 状态是否一致？
   - 周期时间是否一致？
    ↓
6. 如果不一致 → 更新本地数据库
   UPDATE user_subscriptions
   SET status = creem_status,
       current_period_end = creem_period_end
   WHERE id = subscription_id
    ↓
7. 记录同步日志
   INSERT INTO sync_logs (...)
    ↓
8. 返回同步结果
```

### 状态对比逻辑

| 场景 | 本地状态 | Creem 状态 | 操作 |
|------|---------|-----------|------|
| **正常** | active | active | 无需更新 |
| **已取消** | canceled | canceled | 无需更新 |
| **Webhook 失败** | active | canceled | 更新为 canceled |
| **周期更新** | active | active | 更新 period_end（如果相差 > 1 小时） |
| **已过期** | active | expired | 更新为 expired |

## 🔍 故障排查

### Q1: 同步任务没有运行？

**检查清单**:
1. ✅ 是否已部署到 Vercel？（本地不会自动运行）
2. ✅ `vercel.json` 是否正确配置？
3. ✅ 环境变量 `CRON_SECRET` 是否设置？
4. ✅ 在 Vercel Dashboard → Cron Jobs 中查看执行日志

### Q2: Creem API 调用失败？

**排查步骤**:
1. 检查 `CREEM_API_KEY` 是否正确
2. 确认 API Key 有权限访问订阅信息
3. 查看 Creem API 限流状态
4. 检查网络连接

### Q3: 同步更新了不应该更新的订阅？

**原因分析**:
- 时间格式不一致
- 时区问题
- Creem 返回的时间与预期不符

**解决方法**:
- 检查时间对比逻辑
- 增加日志输出
- 调整时间容差

### Q4: 同步日志表增长太快？

**解决方法**:
```sql
-- 定期清理旧日志
SELECT cleanup_old_sync_logs();

-- 或创建定时任务每月清理一次
```

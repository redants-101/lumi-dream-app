# 🧪 跨标签页认证同步测试指南

## 📋 修复内容

### 问题描述
- **原问题**：sessionStorage 不跨标签页共享，导致新标签页初始显示"未登录"状态，1-2秒后才更新为"已登录"
- **影响范围**：用户体验不一致，导航栏用户按钮闪烁

### 解决方案
1. ✅ 将 `lumi_auth_cache` 从 **sessionStorage** 改为 **localStorage**
2. ✅ 保持 5 分钟缓存有效期（自动过期机制）
3. ✅ 统一清理逻辑（所有用户数据集中在 `use-auth.ts` 清理）
4. ✅ 跨标签页共享认证状态

---

## 🔧 代码变更

### 1. `hooks/use-auth.ts`

#### 变更 1：存储方式从 sessionStorage → localStorage
```typescript
// ❌ 修改前
sessionStorage.setItem(AUTH_CACHE_KEY, JSON.stringify(cache))
sessionStorage.getItem(AUTH_CACHE_KEY)

// ✅ 修改后
localStorage.setItem(AUTH_CACHE_KEY, JSON.stringify(cache))
localStorage.getItem(AUTH_CACHE_KEY)
```

#### 变更 2：新增统一清理函数
```typescript
const clearAllUserData = () => {
  localStorage.removeItem(AUTH_CACHE_KEY)        // 认证缓存
  localStorage.removeItem(TIER_STORAGE_KEY)      // 用户层级
  localStorage.removeItem(USAGE_STORAGE_KEY)     // 使用数据
  // 保留：lumi-cookie-consent（用户偏好）
}
```

#### 变更 3：signOut 使用统一清理
```typescript
const signOut = async () => {
  await fetch("/api/auth/logout", { method: "POST" })
  setUser(null)
  clearAllUserData()  // ✅ 统一清理
}
```

### 2. `contexts/usage-limit-context.tsx`

#### 移除重复清理逻辑
```typescript
// ❌ 修改前：重复清理 localStorage
localStorage.removeItem(TIER_STORAGE_KEY)
localStorage.removeItem(STORAGE_KEY)

// ✅ 修改后：只重置 React 状态
// localStorage 清理已由 use-auth.ts 的 clearAllUserData() 统一处理
setSubscription(null)
setUsageData(null)
setIsLimitReached(false)
```

### 测试 4：多标签页登出同步

**目标**：验证在一个标签页登出后，其他标签页也能感知到

#### 步骤：
1. **标签页 A & B**：同时打开两个标签页，都显示已登录状态
2. **标签页 A**：点击登出
3. **标签页 B**：刷新页面

#### 预期结果：
- ✅ 标签页 A：立即跳转（Home/Pricing 刷新，Dashboard 跳转到 Pricing）
- ✅ 标签页 B：刷新后显示未登录状态（因为 localStorage 已清空）
- ✅ 无残留缓存数据

**注意**：如果不刷新标签页 B，它仍会显示已登录（因为 React 状态未更新）。这是正常行为，因为：
- localStorage 只是缓存，真实状态由 Supabase 认证决定
- 标签页 B 下次 API 调用时会收到 401 错误，自动登出

## 🚨 潜在风险与缓解

### 风险 1：localStorage 容量限制（5-10MB）

**缓解措施**：
- ✅ 只存储必要数据（User 对象精简）
- ✅ 5 分钟自动过期机制
- ✅ 登出时主动清理

### 风险 2：跨标签页状态不实时同步

**场景**：用户在标签页 A 登出，标签页 B 不刷新仍显示已登录

**缓解措施**：
- ✅ 下次 API 调用时会收到 401 → 自动登出
- ✅ 用户刷新页面时会检测到缓存已清空
- ❓ **可选增强**：使用 `storage` 事件监听跨标签页同步（下一阶段优化）

### 风险 3：用户手动清除 localStorage

**影响**：缓存丢失，需要重新加载用户数据

**缓解措施**：
- ✅ 已有后台自动验证机制
- ✅ 不影响功能，只是稍微慢一点（1-2秒）

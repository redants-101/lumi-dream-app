# 📊 订阅到期处理机制说明

## 🎯 核心问题

**问题**：当 `status === "canceled"` 的订阅到期后，系统如何发现并处理？

---

## 🔍 当前机制（3 种）

### 机制 1：被动检查（API 调用时）✅

**触发时机**：每次用户访问页面，前端调用 API

**检查位置**：
- `/api/usage` - Home 页面调用
- `/api/user-info` - Dashboard 调用
- `/api/subscription/manage` - Pricing 页面调用

**检查逻辑**：
```typescript
// 每次 API 调用时
const isNotExpired = subscription.current_period_end && 
                    new Date(subscription.current_period_end) > new Date()

if (!isNotExpired) {
  // 已过期：返回 Free
  tier = "free"
}
```

**效果**：
- ✅ 用户访问时立即检测
- ✅ 无需定时任务
- ⚠️ 用户不访问就不检测

**示例**：
```
12月9日 23:59 - 用户访问：
  └─ period_end > now? → true
  └─ 显示 Pro ✅

12月10日 00:01 - 用户访问：
  └─ period_end > now? → false
  └─ 显示 Free ✅
```

---

### 机制 2：Creem Webhook（主动通知）⚠️

**触发时机**：Creem 检测到订阅过期

**事件类型**：`subscription.expired`

**Webhook 处理**（第 590-665 行）：
```typescript
case "subscription.expired":
  handled = await handleSubscriptionExpired(eventData)
  break

async function handleSubscriptionExpired(data) {
  // 1. 更新数据库
  await supabase.update({
    status: "expired",
    tier: "free",  // 立即降级
  })
  
  // 2. 发送续费失败邮件
  await sendRenewalFailedEmail(...)
}
```

**问题**：
- ✅ 适用场景：**自动续费失败**（扣款失败）
- ❌ 不适用场景：**用户主动取消**

**为什么？**
- 用户主动取消：Creem 设置 `auto_renew = false`
- 到期时：Creem **不会尝试扣款**
- **可能不会**发送 `subscription.expired` 事件
- 或者延迟很久才发送

---

### 机制 3：定时同步任务（主动检查）✅

**文件**：`app/api/cron/sync-subscriptions/route.ts`

**触发频率**：每 6 小时（配置在 `vercel.json`）

**功能**：
```typescript
// 1. 查询所有活跃和已取消的订阅
const subscriptions = await supabase
  .from("user_subscriptions")
  .select("*")
  .in("status", ["active", "canceled"])  // ✅ 包含 canceled
  .not("creem_subscription_id", "is", null)

// 2. 从 Creem 获取最新状态
for (const subscription of subscriptions) {
  const creemSubscription = await creemClient.getSubscription(
    subscription.creem_subscription_id
  )
  
  // 3. 对比状态
  const needsUpdate = (
    subscription.status !== creemSubscription.status ||
    // 其他字段...
  )
  
  // 4. 更新不一致的记录
  if (needsUpdate) {
    await supabase.update({
      status: creemSubscription.status,
      // ...
    })
  }
}
```

**效果**：
- ✅ 每 6 小时自动同步
- ✅ 检测状态不一致
- ✅ 自动修复
- ⚠️ 最多延迟 6 小时

### 优化方案（可选）

#### 方案 1：添加专门的过期检测定时任务

**新建**：`app/api/cron/check-expired-subscriptions/route.ts`

```typescript
export async function GET() {
  // 1. 查询所有 canceled 状态的订阅
  const { data: canceledSubscriptions } = await supabase
    .from("user_subscriptions")
    .select("*")
    .eq("status", "canceled")
    .lt("current_period_end", new Date().toISOString())  // 已过期
  
  // 2. 批量更新为 Free
  for (const sub of canceledSubscriptions) {
    await supabase
      .from("user_subscriptions")
      .update({
        status: "expired",
        tier: "free",
      })
      .eq("id", sub.id)
    
    console.log(`[Cron] Downgraded user ${sub.user_id} to Free`)
  }
  
  return { processed: canceledSubscriptions.length }
}
```

**触发**：每天运行一次（如凌晨 2 点）

```json

{
  "crons": [
    {
      "path": "/api/cron/check-expired-subscriptions",
      "schedule": "0 2 * * *"  // 每天凌晨 2 点
    }
  ]
}
```

**优势**：
- ✅ 主动检测过期
- ✅ 数据库状态同步
- ✅ 可以发送通知邮件

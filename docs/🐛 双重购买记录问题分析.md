# 🐛 双重购买记录问题分析

## 🔍 问题现象

**用户操作**：Free 用户升级到 Basic

**预期结果**：1 条 `subscription_created` 记录

**实际结果**：2 条记录
1. `subscription_created` - 首次购买
2. `subscription_renewed` - 续费延长（❌ 不应该出现）

**订阅时间异常**：
- 第 1 条：`2025-12-10`（正常 30 天）
- 第 2 条：`2026-01-09`（延长了 60 天）

## 🎯 问题根源

### 根本原因

**Creem 在一次购买中发送了多个 webhook**：

1. `subscription.active` - 订阅激活通知
2. `subscription.paid` - 支付成功通知
3. `checkout.completed` - 结账完成通知

**我们的处理**：
- `subscription.paid` → 调用 `handleCheckoutCompleted`（第 1 次）
- `checkout.completed` → 调用 `handleCheckoutCompleted`（第 2 次）

**结果**：
- 第 1 次处理：创建订阅
- 第 2 次处理：检测到有订阅 → 误判为续费 → 延长订阅

---

## ⚠️ 为什么会误判为续费？

### 时间线

```
13:13:05 - 用户完成支付
  ↓
13:13:07 - Webhook 1: subscription.active（未处理）
  ↓
13:13:07 - Webhook 2: subscription.paid
           └─ 调用 handleCheckoutCompleted
           └─ 查询订阅：无
           └─ 创建订阅（period_end: 2025-12-10）
  ↓
13:13:20 - Webhook 3: checkout.completed
           └─ 调用 handleCheckoutCompleted
           └─ 查询订阅：有！（刚创建的）
           └─ 相同套餐 → 误判为续费
           └─ 延长订阅（period_end: 2026-01-09）
```

**关键**：第 3 个 webhook 处理时，数据库已经有订阅记录了（第 2 个 webhook 创建的）！

## ✅ 解决方案

### 方案 1：添加幂等性检查（推荐）⭐

**思路**：使用 Creem 的 `checkout_id` 或 `payment_id` 去重

```typescript
// 检查是否已处理过此次购买
const { data: existingHistory } = await supabase
  .from("subscription_history")
  .select("id")
  .eq("creem_payment_id", data.id)  // 使用支付 ID 去重
  .single()

if (existingHistory) {
  console.log("[Webhook] ✅ Already processed this payment, skipping")
  return true  // 返回成功，但不重复处理
}
```

async function handleCheckoutCompleted(data: any): Promise<boolean> {
  console.log("\n💳 [Webhook] Checkout completed:", data.id)
  
  // ✅ 幂等性检查：是否已处理过此次支付
  const paymentId = data.id
  const { data: existingHistory } = await supabase
    .from("subscription_history")
    .select("id, event_type, creem_payment_id")
    .eq("creem_payment_id", paymentId)
    .maybeSingle()  // 使用 maybeSingle 避免没有记录时报错
  
  if (existingHistory) {
    console.log(`[Webhook] ✅ Payment ${paymentId} already processed`)
    console.log(`[Webhook] Previous event: ${existingHistory.event_type}`)
    console.log("[Webhook] Skipping duplicate processing")
    return true  // 返回成功，但不重复处理
  }
  
  console.log(`[Webhook] ✅ New payment, proceeding with processing`)
  
  // ... 原有的处理逻辑
}

## 📋 Creem Webhook 事件说明

### 首次购买触发的事件

根据日志，Creem 在首次购买时发送：

1. `subscription.active` - 订阅激活
2. `subscription.paid` - 支付成功
3. `checkout.completed` - 结账完成

**建议处理策略**：
- `subscription.active` - 可忽略（或记录日志）
- `subscription.paid` - **只处理续费**，首次购买跳过
- `checkout.completed` - 处理首次购买和手动续费

---

### 自动续费触发的事件

到期时 Creem 可能只发送：

1. `subscription.paid` - 续费支付成功

**处理**：
- ✅ 延长订阅
- ✅ 记录历史

## 🎯 问题总结

**原因**：
- Creem 发送多个 webhook
- `subscription.paid` 和 `checkout.completed` 都被处理
- 第 2 个 webhook 误判为续费

**影响**：
- 用户订阅被延长（从 30 天变 60 天）
- 虽然对用户有利，但不符合预期
- 历史记录不准确

**修复**：
- ✅ 添加幂等性检查
- ✅ 区分首次购买和续费
- ✅ 添加 `subscription.active` 处理
